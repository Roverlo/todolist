# Windows 免安装版验收流程

每次发布记录源码提交、EXE 路径、字节数、SHA-256、Windows/WebView 环境、测试日期及证据目录。必须测试待交付的 EXE；修改代码后重新构建，再复测失败场景及关联回归。

## 数据与执行顺序

1. 检查主分支、功能分支和工作区，确认推送权限。合并已验证修改并构建 `npm run tauri:build -- --no-bundle`，通过 `scripts/create-portable.ps1` 生成单文件 EXE。
2. 备份用户 Documents/ProjectTodo 全目录，逐文件核对 SHA-256，保存恢复命令。测试使用独立 `PROJECTTODO_TEST_DATA_DIR` 和 `WEBVIEW2_USER_DATA_FOLDER`，仅放虚构任务、随记和测试凭据。
3. 使用 computer-use 的窗口枚举、截图/可访问性树、点击和键盘 API 操作 EXE。每次动作后重新观察；不能用旧截图坐标或旧控件索引操作新页面。
4. 运行下表的功能流程；自动化补充边界组合。记录实际执行方式：CUA（Windows 界面）、AUTO（脚本）、LIMIT（环境限制）、FAIL（未解决）。没有执行的检查不能写 PASS。
5. 问题先记录复现步骤、实际结果和预期结果，在原功能分支修复，留下最小回归检查。重新执行失败步骤及相关检查，合入 main 后重新打包。
6. 验证退出后测试进程消失、用户数据哈希未变化、交付 EXE 与被测产物哈希一致。保留报告、日志和必要截图；测试记录及备份不提交仓库。

## 可重复运行的自动化

在 `app` 目录依次运行，避免多个临时开发服务器争抢资源：

```powershell
npm run lint
npm run build
node scripts/test-ai-compat.mjs
npm run test:notes
node scripts/test-progress-save.mjs
node scripts/test-backup.mjs
node scripts/test-task-workflow.mjs
node scripts/test-recurring.mjs
node scripts/test-ui-regressions.mjs
node scripts/test-note-workflow.mjs
./scripts/test-portable.ps1 -Executable '<交付 EXE 绝对路径>' -EditorWorkflow
```

原生工作流测试前退出其他 ProjectTodo 进程，避免单实例锁唤醒用户窗口。Computer-use 会话中窗口生命周期直接用其 API 操作；不要混用其他 Windows UI 自动化接口。

真实模型的提取质量、真实同步服务和不同 Windows/WebView 版本应独立记录覆盖情况。本机模拟响应只能证明传输、兼容与交互流程，不能证明所有供应商和模型质量。

## 原生关闭故障回归

在 `app` 目录运行 `./scripts/test-portable.ps1 -Executable <EXE路径> -WindowRecovery crash`，随后按脚本提示，用 Computer Use 或人工点击原生 X 和“退出程序”。再以 `-WindowRecovery busy` 运行，选择“继续等待”。脚本会验证正常关闭监听、原生超时、取消后不误退出、恢复后的内容及最终退出；全部使用隔离数据并核对原有数据哈希。

渲染崩溃测试验证关闭兜底，不等于已经查明用户设备上触发白屏的原因。不要把“禁用全部脚本后仍能关闭”当作对运行中崩溃的覆盖。
