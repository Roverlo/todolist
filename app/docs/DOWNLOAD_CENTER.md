## 实现与数据边界

Rust 单一工作线程持有 aria2 子进程和下载日志；仅监听本机回环地址，JSON-RPC 使用 Windows BCrypt 生成的随机令牌。进度不进入任务/随记 Zustand 数据，也不触发其保存。切换页面、窗口隐藏到托盘不会停止下载。显式退出时暂停并写入续传控制文件；`--stop-with-process` 让引擎在父进程意外结束后退出。

`Documents/ProjectTodo/downloads/history.json` 独立保存下载记录和设置，临时文件写入、刷盘、重命名，写入失败保留原文件并提示。引擎释放在同目录 `engine-<版本>/`，默认文件保存到系统 Downloads/ProjectTodo；用户可选择其他绝对目录。测试数据目录覆盖同时隔离引擎、日志及默认下载目录。

下载日志不属于现有“任务/随记备份”或云同步内容，避免将本机绝对路径、下载链接及大文件同步到其他设备。需要迁移下载时，退出应用后同时复制 `downloads/history.json`、实际文件及同目录的 `.aria2` 控制文件，保留原保存路径。手工修改路径不在自动迁移范围内。

断点续传取决于服务器 Range 支持及有效链接。缺少 `.aria2` 控制文件且已有同名文件时拒绝恢复，不猜测文件归属。自动命名遇到已有文件、续传文件或下载记录时添加 ` (1)` 等后缀，保留已有文件；手动指定名称冲突时仍提示修改。移除记录停止任务并保留已下载文件，不自动运行任何下载文件。仅支持普通链接，不处理登录、Cookie、网盘网页或浏览器接管。

表单只展示链接识别数量，不再请求文件名预览或提供重命名入口；点击开始下载时 Rust 为每个链接解析名称。依次使用服务器 `Content-Disposition`（优先 UTF-8 `filename*`）、重定向后的 URL 路径、原 URL 路径，均无合法名称则使用 `download.bin`。查询参数不进入文件名，拒绝路径和 Windows 保留名称。HEAD 不支持或未返回文件名时尝试一个字节的 GET Range，仅读取响应头后丢弃正文；服务器不支持预识别时仍允许开始下载并自动命名。HEAD 大小从响应头读取，不使用空正文的长度。浏览器预览可以解析粘贴文字及本地文件，但不执行原生服务器识别或真实下载。带签名或密码参数的实际链接不进入源码、提交或公开报告。

导入支持 TXT、CSV、TSV 和 Excel `.xlsx`，旧版 `.xls` 提示另存格式。文本支持 UTF-8、带 BOM 的 UTF-16，以及 GB18030 回退；CSV / TSV 复用 PapaParse，`.xlsx` 复用现有生产锁文件中的 JSZip（由 docx 引入），不增加生产依赖。读取多个工作表的文字、富文本、超链接和参数为字符串常量的 HYPERLINK 公式；不运行公式或访问外部数据。不支持密码加密的工作簿。

输入最多 1 MiB 字符、500 条去重后的链接；一次最多选择 20 个文件，单文件最多 10 MiB，Excel 读取的 XML 解压总量最多 20 MiB。一次多文件导入全部解析成功后才合并到输入框，失败时保留原内容。签名参数保持原始编码，不用 URL 序列化重写；只在相邻 URL 之间切分英文逗号/分号/竖线，保留查询字符串内部的同类字符。若标点本身属于 URL，应使用百分号编码以避免与自然语言边界混淆。

批量创建沿用逐项原生下载命令，显示进度并可停止后续添加；当前处理中的链接会先完成。成功项从待添加列表移出，失败项保留，重试不会重复创建成功项。如果引擎失败但已存在可重试记录，则在下载列表中重试该记录。解析和文件读取均在本机完成，不上传清单文件。

设置：同时下载 1–8 个文件，总限速单位 KiB/s，0 表示不限速；这两项保存后立即作用于当前引擎。界面“单文件分片数”支持 1、4、8、16、32、64，默认沿用此前的 4；旧日志缺少该字段时自动使用 4。新任务、重试和重启恢复使用当前值；已有任务可暂停再继续应用新值。该值仍同时传给 aria2 的 `split` 与 `max-connection-per-server`，实际含义为单文件并行连接上限，并非保证固定数量的物理分块。实际连接数量受 Range 支持、文件大小及服务器限制影响，更多连接不保证更快。保留引擎默认最小分片 20 MiB，小文件可能仅用单连接。参数语义见 [aria2 官方手册](https://aria2.github.io/manual/en/html/aria2c.html#cmdoption-s)。保存目录仅影响新任务。完成通知使用已有 Tauri 通知插件，其展示受系统通知设置影响。

两处下拉使用 `CustomSelect`，保持主题、选中标记及键盘操作一致。组件在原生 `<dialog>` 内时将菜单放在该弹窗的顶层范围内，避免挂在 `body` 后被模态遮挡或禁用；普通页面仍使用原有 `body` 挂载方式。菜单根据窗口可用高度选择方向，并限制高度允许滚动。未新增 UI 依赖。
